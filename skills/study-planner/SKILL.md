## Overview

Most study plans fail because they are just a list of topics with dates
attached. The material gets read once, feels familiar, and is gone by the
following week. This skill builds a different kind of plan: a recurring
weekly timetable that covers many topics at once, ranks them by how much
they count and how weak the user is on them, and runs every topic on a
spaced repetition ladder so old material keeps coming back just before it
would be forgotten. Each week ends with a mixed self-test, and the results
rebuild the next week's plan.

It is built for ongoing study loads — a semester of courses, a
certification spread over months, a set of subjects heading toward one
exam date — rather than a single short push on one topic.

## When to use

- The user is juggling several subjects or topics and wants one weekly
  timetable that covers all of them.
- An exam or deadline is weeks or months away and the user wants a
  revision plan instead of last-minute cramming.
- The user keeps re-reading notes without retaining them and needs
  structure built on recall and spacing.
- The user has limited, fixed study time each week and needs it allocated
  by priority rather than by mood.

## Gather the inputs first

- Ask what subjects or topics the plan covers and break them into chunks
  that each fit in one sitting.
- Ask for the target date — an exam, a deadline, a presentation — and
  work backward from it.
- Ask how many days a week the user can study and how many minutes a day
  are realistic. Build to the honest number, not the hopeful one.
- Ask how strong the user already is on each topic and mark each one
  weak, fair, or strong.

## Build the topic inventory

- Rank topics by two things together: how much they count toward the
  goal, and how weak the user is on them.
- Put weak and heavy topics first in the rotation. Give strong topics
  only maintenance reviews.
- Split any topic that cannot be covered in one sitting into named parts
  before scheduling it.

## Lay out the week

- Schedule new material early in the week so its first reviews still fit
  inside the same week.
- Run every topic on a spacing ladder: first review the next day, then
  after 3 days, then after 7 days, then once a week until the target
  date.
- Interleave topics within a day instead of blocking one topic for
  hours, and cap a single sitting at about 50 minutes before a break.
- Place the hardest topic at the time of day the user says their head is
  clearest.
- Leave one day light or empty as the buffer for whatever slips.

## Make every session active

- Open each review with recall — questions, flashcards, or practice
  problems — before any re-reading.
- End each session with a short self-test and record what was missed.
- Carry every missed item into the next session at the shortest spacing
  step, whatever the ladder says.

## Run the weekly cycle

- Close the week with a mixed self-test across all topics and grade it
  honestly.
- Rebuild the next week from the results: weak topics get more sessions,
  strong topics drop to maintenance.
- When a session is missed, shift the ladder forward rather than
  doubling sessions the next day.

## Present the plan

- Give the plan as a day-by-day list with the topic, the kind of session
  (new, review, or test), and the minutes for each.
- State the target date the plan is built against and the total weekly
  time it asks for.
- Offer to put the sessions on the user's calendar or task list when
  they want the plan tracked, and only add them after they agree.
