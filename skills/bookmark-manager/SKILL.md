# Bookmark Manager

## Overview

Bookmarks fail the same way everywhere: saved enthusiastically, never organized, never found again.

A working system needs: instant capture, a tagging convention, full-text search, and regular pruning.

Modern approach: bookmarks as a searchable database (tags + descriptions + full-text), not a folder tree.

The test: can you find any saved link in under 30 seconds, months later?

## When to use

- Losing useful links saved 'for later'
- Research with many web sources to organize
- Bookmarks scattered across browsers and devices
- Teams sharing curated link collections
- Replacing browser bookmark bar chaos with a real system

## Core concepts

- **Capture in one keystroke.**
  Saving must take <5 seconds from anywhere: browser extension, mobile share sheet. Friction kills capture.
- **Tags over folders.**
  Multi-dimensional tagging (topic, project, type) beats single-location folders. A link can be 'design' + 'project-x' + 'tutorial'.
- **Descriptions matter.**
  One line on why you saved it. Future you won't remember; the description is the retrieval key.
- **Full-text search.**
  Search titles, URLs, tags, descriptions — and page content if your tool archives it. Search is the primary retrieval path.
- **Read-later vs. bookmark.**
  Read-later = will read soon (temporary). Bookmark = reference worth keeping (permanent). Different tools, different lifecycles.
- **Sync everywhere.**
  Bookmarks on all browsers and devices via sync or a web-based manager. A bookmark you can't reach is lost.
- **Collections for sharing.**
  Curated public/private collections for teams, projects, or publishing. Bookmarks become shared knowledge.
- **Archive page content.**
  Link rot is real. Tools that save page snapshots protect against dead links for critical references.

## Practical workflow

1. **Pick one home.**
   Browser sync, dedicated manager, or notes app — one primary place. Decide read-later vs. bookmark split.
2. **Install capture everywhere.**
   Extension on desktop browsers, share-sheet on mobile. Test: save a link in under 5 seconds.
3. **Define tag taxonomy.**
   10-20 core tags: topics, projects, types (tutorial, tool, reference). Consistent, lowercase, documented.
4. **Add descriptions.**
   Every save gets one line: why this, for what. Takes 10 seconds, saves hours of 'why did I save this?'
5. **Triage weekly.**
   Review recent saves: tag properly, delete the mistaken, move read-later items that became references.
6. **Prune quarterly.**
   Dead links, obsolete tools, completed projects. A bookmark collection is a garden.
7. **Build shared collections.**
   For teams/projects: curated collections with descriptions. Review and update on a cadence.
8. **Back up exports.**
   Periodic export of the bookmark database. Links are assets; don't trust a single service blindly.

## Common pitfalls

- **Bookmark bar sprawl.**
  200 unsorted bookmarks in nested folders named 'stuff.' Unfindable = unsaved.
- **No descriptions.**
  Mystery links with bare titles. Six months later, unopenable because context is gone.
- **Saving without triaging.**
  Capture with no weekly review becomes a junk drawer. The triage habit is the system.
- **Folders-only organization.**
  Deep folder trees where each link lives in exactly one place. Tags reflect how memory actually works.
- **Read-later confusion.**
  'Read later' items aging into bookmarks. Separate lifecycles: read-later gets triaged weekly, bookmarks persist.
- **Never pruning.**
  Dead links and 2019 tools accumulating. Quarterly pruning keeps retrieval fast and trust high.
- **Browser-only storage.**
  Bookmarks trapped in one browser profile. Sync or use a portable manager — machines die, profiles corrupt.
- **No search habit.**
  Manually browsing folders instead of searching. Train the search-first reflex; it's 10x faster.
