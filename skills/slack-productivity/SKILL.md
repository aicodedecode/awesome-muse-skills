# Slack Productivity

## Overview

Slack is where work conversation happens — and where attention goes to die without discipline.

Productive Slack = intentional channel architecture, ruthless notification control, threads for side discussions, and search-first retrieval.

For teams: norms matter more than features. Write them down, model them, enforce kindly.

## When to use

- Slack feels noisy and interruptive
- Channels proliferate with no clear purpose
- Important messages get lost in scroll
- Setting team communication norms
- New to Slack or onboarding a team to it

## Core concepts

- **Channel architecture.**
  Prefixes by purpose: #team-*, #proj-*, #help-*, #social-*, #announce-*. Archived when done. A channel needs a topic and an owner.
- **Notification control.**
  Default: mentions only. Mute noisy channels. Do Not Disturb scheduled. Notification preferences are personal productivity infrastructure.
- **Threads.**
  Side discussions in threads, always. Channel = announcements/decisions; threads = discussion. Unthreaded chatter buries signal.
- **Channel vs. DM.**
  DMs for private/1:1; channels for anything others might need later. Default to channels — DMs create invisible silos and repeat questions.
- **Search-first.**
  Slack search with filters (in:, from:, before:, has:link). Most questions were answered before — search before asking.
- **Workflows and apps.**
  Workflow Builder for intake forms, standups, approvals. Integrate GitHub/Jira/Drive so updates arrive where work happens.
- **Status and DND.**
  Set status honestly (focus, OOO, in meeting). DND during deep work. Status is communication, not decoration.
- **Huddles and clips.**
  Quick voice huddle beats 20-message threads for complex topics. Clips for async walkthroughs across time zones.

## Practical workflow

1. **Design channels.**
   Write the architecture: prefixes, purpose per channel, owner per channel. Archive dead channels immediately.
2. **Set notification defaults.**
   Team guidance: mentions-only default, mute liberally, DND hours respected. Leaders model it first.
3. **Enforce threads.**
   Make threading the norm: reply in thread, summarize decisions back to channel. Gentle reminders beat silent suffering.
4. **Write the norms doc.**
   When to DM vs. channel, response-time expectations, @channel/@here rules, thread etiquette. Pin it in #announcements.
5. **Configure workflows.**
   Intake forms (IT, design requests), recurring standups, approval flows. Automate the repetitive asks.
6. **Learn search.**
   Filters and modifiers. Practice: find that decision from last month in under a minute.
7. **Integrate tools.**
   GitHub, Jira, Drive, calendar — notifications routed to the right channels, not everyone's DMs.
8. **Audit quarterly.**
   Archive dead channels, review integrations for noise, update the norms doc. Slack rots without gardening.

## Common pitfalls

- **@channel/@here abuse.**
  Broadcasting to everyone for trivia. Reserve for genuine urgency; abuse trains everyone to mute the channel.
- **DM default.**
  Discussing work in DMs that teammates need. Default to channels; DMs for truly private matters.
- **Unthreaded pile-ons.**
  30-message discussions in the main channel burying everything else. Threads exist — use them relentlessly.
- **Notification firehose.**
  Default settings + 50 channels = 200 pings daily. Mentions-only + mutes + DND is the only sustainable config.
- **Channel sprawl.**
  #project-x, #projectx, #proj-x-final. Naming convention + archiving or discovery dies.
- **No response norms.**
  Is 5 minutes expected? 24 hours? Undefined expectations create anxiety. Write them down.
- **Decisions in scroll.**
  Decisions made mid-thread, never summarized. Summarize decisions back to the channel; pin them.
- **Always-on culture.**
  Evening/weekend pings normalized. DND + delayed send + norms protect off-hours — leadership must model it.
