# Pattern Checklist

Use this reference when the task concerns product flows, repeated UX solutions, or page structures.

## Distinctions

- Component: a reusable UI unit with states and variants.
- Pattern: a reusable solution to a user/product problem, composed of components.
- Template: a recurring page or layout structure.

Examples:

```txt
Input = component
Search with filters = pattern
Catalog page = template
```

## Patterns to look for

- Authentication and onboarding
- Search, filters, and sorting
- Checkout or multi-step completion
- Dashboard summary
- Settings and preferences
- Empty states
- Error recovery
- Confirmation and destructive actions
- Table actions
- Notifications and alerts
- Upload/download
- Permissions and access control
- Navigation and wayfinding

## Pattern documentation format

```md
# Pattern: Name

## Scenario
Where this pattern appears.

## User intent
What the user wants to accomplish.

## Problem
What UX problem the pattern solves.

## Components used
List of components.

## Layout rules
Structure, spacing, responsive behavior.

## Interaction rules
States, transitions, validation, feedback.

## Accessibility rules
Keyboard flow, focus order, announcements, contrast, motion.

## Examples from Figma
Pages, frames, screenshots.

## Anti-patterns
Incorrect usages found or anticipated.
```
